# Map and Images

Приложение на React Native (Expo) с картой OpenStreetMap, изображениями, привязанными к
маркерам, и локальной базой данных SQLite.

Карта реализована через `react-native-webview` + Leaflet + тайлы OpenStreetMap (вместо
`react-native-maps`, который на Android требует Google Maps API key и нативной сборки).

## Запуск

```bash
npm install
npx expo start
```

Далее откройте проект в Expo Go на устройстве.

## Функциональность

- Долгое нажатие по карте добавляет маркер (подпись «Точка N»).
- Нажатие на маркер на карте открывает экран деталей.
- На экране деталей: координаты, дата создания, список изображений.
- «Добавить изображение» — выбор нескольких фото из галереи (`expo-image-picker`).
- Удаление отдельного изображения.
- Удаление маркера вместе с изображениями (с подтверждением).
- Навигация назад к карте (кнопка в шапке и кнопка «Вернуться к карте»).
- Все маркеры и изображения сохраняются в локальной БД и остаются после перезапуска.
- Обработка ошибок: инициализация БД, CRUD-операции, загрузка карты/тайлов, сообщения
  из WebView, права доступа, исключения image picker, отсутствующий маркер, навигация.

## Локальная база данных

Используется `expo-sqlite` без ORM: для MVP достаточно прямых параметризованных SQL-запросов
и явного контроля транзакций. Файл БД: `markers.db`.

### Схема

```sql
CREATE TABLE IF NOT EXISTS markers (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  latitude REAL NOT NULL,
  longitude REAL NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS marker_images (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  marker_id INTEGER NOT NULL,
  uri TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_marker_images_marker_id
  ON marker_images (marker_id);
```

### Версионирование и операции

- Версия схемы хранится в `PRAGMA user_version` (сейчас `1`).
- При первом запуске выполняется миграция `0 -> 1` в транзакции.
- При каждом открытии соединения включается `PRAGMA foreign_keys = ON`.
- Создание/чтение маркеров, добавление/удаление изображений, чтение изображений маркера.
- Удаление маркера выполняется в транзакции и удаляет связанные изображения.
- Даты SQLite (`CURRENT_TIMESTAMP`, UTC) преобразуются в миллисекунды для UI.

## Обработка ошибок

- Слой `database/` оборачивает ошибки SQLite в сообщения с названием операции и пишет
  подробности в консоль в режиме разработки.
- `DatabaseContext` централизованно хранит последнюю ошибку, пробрасывает её в UI и
  поддерживает повторную инициализацию БД.
- При ошибке открытия БД показывается экран с кнопкой «Повторить».
- Операции удаления проверяют, что запись действительно существует.
- При добавлении изображения проверяется существование маркера.
- Экраны показывают ошибки через `ErrorBanner`, а долгие операции блокируют повторное
  нажатие кнопок.

```

  _layout.tsx              корневой Stack + DatabaseProvider + ErrorBoundary
  index.tsx                экран карты
  marker/[id].tsx          экран деталей маркера
components/
  Map.tsx                  WebView + Leaflet + OSM
  ImageList.tsx            сетка изображений с удалением
  ErrorBanner.tsx          сообщение об ошибке
context/
  DatabaseContext.tsx      подключение к SQLite, CRUD, loading/error
database/
  schema.ts                открытие БД, схема, версионирование
  operations.ts            SQL-операции и маппинг строк в типы приложения
  errors.ts                единый формат ошибок БД
lib/
  mapHtml.ts               HTML/JS карты для WebView
types.ts                   типы приложения и валидация сообщений WebView
```

## Ограничения

- Изображения хранятся как локальные URI, полученные от `expo-image-picker`. Если система
  очистит кэш или пользователь удалит исходный файл из галереи, изображение может стать
  недоступным. Копирование файлов в постоянное хранилище в MVP не реализовано.
- Для загрузки карты нужен интернет: Leaflet подключается с unpkg, тайлы — с
  `tile.openstreetmap.org`.
- Используется публичный тайл-сервер OSM; для продакшена нужен собственный провайдер
  тайлов согласно [политике OSM](https://operations.osmfoundation.org/policies/tiles/).
- Приложение рассчитано на мобильную среду (Expo Go). Web-платформа для SQLite отдельно
  не настраивалась.
- Данные локальные: синхронизации между устройствами, экспорта и импорта нет.
